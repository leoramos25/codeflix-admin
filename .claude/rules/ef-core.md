# EF Core persistence

> **Always in effect.** This rule is loaded for every task in this repository and applies to
> every change in `Codeflix.Catalog.Infra.Data.EF`, to the DbContext registration in the Api,
> and to any domain change that alters what is persisted — no exceptions without asking first.

EF Core is an infrastructure detail. The domain model is designed first, as if no ORM existed,
and the mapping adapts to it — never the other way round. If a mapping seems to require
changing an aggregate (a public setter, a parameterless constructor, a navigation property,
a foreign-key property), stop and ask: the mapping is wrong, not the aggregate.

Stack: EF Core 9 + `Pomelo.EntityFrameworkCore.MySql` against MySQL 8. Only
`Codeflix.Catalog.Infra.Data.EF` references EF packages (the Api references it only to
register the context).

## DbContext

```csharp
public class CodeflixCatalogDbContext(DbContextOptions<CodeflixCatalogDbContext> options)
    : DbContext(options)
{
    public DbSet<Genre> Genres => Set<Genre>();                              // aggregate roots
    public DbSet<GenresCategories> GenresCategories => Set<GenresCategories>(); // join models

    protected override void OnModelCreating(ModelBuilder modelBuilder) =>
        modelBuilder.ApplyConfigurationsFromAssembly(typeof(CodeflixCatalogDbContext).Assembly);
}
```

- One `DbSet` per **aggregate root** and per **join model** — never for an entity internal to
  an aggregate. Expression-bodied `=> Set<T>()`, plural name.
- `OnModelCreating` only calls `ApplyConfigurationsFromAssembly`. No inline mapping there, no
  `[Table]`/`[Key]`/`[MaxLength]` attributes on domain classes — the Domain stays free of EF.
- Registered in `Api/Configurations/ConnectionsConfiguration.cs` from the `CatalogDb`
  connection string with `UseMySql(cs, ServerVersion.AutoDetect(cs))`; nowhere else.

## Entity configurations

Every persisted type gets an explicit `IEntityTypeConfiguration<T>` in `Configurations/`,
named `<Entity>Configuration`, even when conventions would produce the same schema — the
configuration file is the single place where the table shape is read and reviewed.

```csharp
public class CategoryConfiguration : IEntityTypeConfiguration<Category>
{
    public void Configure(EntityTypeBuilder<Category> builder)
    {
        builder.HasKey(category => category.Id);
        builder.Property(category => category.Name).HasMaxLength(255);
        builder.Property(category => category.Description).HasMaxLength(10_000);
    }
}
```

- **`HasKey(x => x.Id)` explicitly.** Ids are `Guid` generated by the domain (`Entity`
  constructor) → `char(36)`; never let the database generate them.
- **Every string gets `HasMaxLength` matching the aggregate's `Max<Field>Size` constant.**
  Without it MySQL creates `longtext`, which cannot be indexed and diverges from the domain
  rule. Required strings also get `IsRequired()`.
- **Read-only collections of ids are not columns.** Call `builder.Ignore(x => x.<Relation>s)`
  for every `IReadOnlyCollection<Guid>` the aggregate exposes; the relation lives in a join
  model (see the aggregate-relationships rule). Do not rely on EF happening to skip it.
- **Enums persist as `int`** (EF default). Never reorder or renumber an existing enum member;
  add new members at the end with an explicit value.
- `DateTime` is UTC, persisted as `datetime(6)`. No value converter needed.

## How EF builds an aggregate

Aggregates have no parameterless constructor and only private setters, and that is fine:

- EF binds the **public constructor** by matching parameter names to property names
  (`Genre(string name, bool isActive)` ↔ `Name`, `IsActive`), then assigns the remaining
  mapped properties (`Id`, `CreatedAt`) through their private setters.
- The constructor therefore runs on every materialisation, including `Validate()` and the
  initialisation of backing collections. Keep constructor parameter names identical to the
  property names, and keep constructors free of side effects other than assigning state.
- If a constructor parameter has no matching mapped property, EF cannot use it — add the
  property mapping or ask; do not add a private constructor just for EF.

## Join models

A many-to-many between aggregates is a persistence-only class in `Models/`, named
`<A>s<B>s` (`GenresCategories`), with its own configuration and `DbSet`:

```csharp
public class GenresCategories(Guid genreId, Guid categoryId)
{
    public Guid GenreId { get; set; } = genreId;
    public Guid CategoryId { get; set; } = categoryId;
    public Genre? Genre { get; set; }        // navigations exist only here, to create the FKs
    public Category? Category { get; set; }
}

builder.HasKey(relation => new { relation.GenreId, relation.CategoryId });
```

- Composite primary key on the two ids — that also makes duplicate pairs impossible in the
  database, so dedupe ids before inserting (`aggregate.<Relation>s.Distinct()`).
- Navigations live **only on the join model**, never on the aggregates. They exist so EF emits
  real foreign keys (`ON DELETE CASCADE`), not to be loaded with `Include`.
- Cascade removes join rows when either side is deleted in MySQL. EF InMemory only cascades
  to **tracked** rows, so a repository's `Delete` removes its own join rows explicitly.

## Repositories and transactions

- Repositories add, update and remove through the change tracker and **never call
  `SaveChanges`**. `UnitOfWork.Commit` is the only place that saves, called once per use case.
- `Get` loads the aggregate tracked (`FindAsync([id], cancellationToken)`) and its join rows
  `AsNoTracking()`, then rehydrates them through the aggregate's public `Add<Relation>`.
- Reads that will not be written back (`Search`, `ListByIds`) use `AsNoTracking()`.
- `Update` of a relation is "remove every join row of this aggregate, add the current ones".
- No `Include`, no lazy loading, no lazy-loading proxies.

## Schema changes

- Any change to a mapped property, a configuration, a join model or a `DbSet` needs a
  migration. Migrations are generated code: **say so and ask before running
  `dotnet ef migrations add`**, then read the generated `Up()` — never hand-edit `Migrations/`.
- Check with `dotnet ef migrations has-pending-model-changes` before finishing. The end-to-end
  suite builds the schema with `EnsureCreated` and integration tests use EF InMemory, so
  neither detects a missing or wrong migration, nor a missing `HasMaxLength`.

## Do not copy these (current deviations)

- `CastMember` has no `CastMemberConfiguration` → `Name` is `longtext`.
- `GenreConfiguration` sets `IsRequired()` on `Name` but no `HasMaxLength` → `longtext`, and
  does not `Ignore(genre => genre.Categories)`.
- `CategoryConfiguration` is `internal` while the others are `public` — use `public`.
- `CategoryRepository.Get` / `CastMemberRepository.Get` call `FindAsync([id, cancellationToken])`,
  passing the token as a key value. Use `FindAsync([id], cancellationToken)`.
